# v7 评分模型对照与发布验证

开始日期：2026-10-01；发布准备日期：2026-10-02。此文为内部证据记录。当前代码准备发布；生产核验结果将在实际部署后补充。没有重算历史评图。

## 实际采纳的修改

- 数值评分模型由 `gpt-5.6-luna` 更新为 `gpt-6-luna`，仍使用 `xhigh`、Responses 图像输入 `detail=high` 和严格结构化输出。点评文字模型仍是 `gpt-5.6-luna`，复拍配对评分保持原合同。
- 普通评图合同更新为 `score-v7-canonical-quality` / `photo-score-v7-canonical-quality`。初评 rubric、五维整数及算术均分没有变；保留 v6 的中性独立高分复核。
- 旧评分缓存和 checkpoint 不作为 v7 命中；历史点评继续可读。v5/v6/v7 均保持下界等级显示，只有 >=8.0 开始高分颜色；成长统计按精确版本分组。
- 添加该模型的官方 Standard 估算费率，旧费率版本保持不变。未知模型或缺失用量继续为未知费用，不用零值替代。
- 生产环境当前显式设置了旧 `OPENAI_SCORE_MODEL`，因此 Cloud Build 的 Deploy 步骤和手动部署入口在更新镜像时同步设置 `OPENAI_SCORE_MODEL=gpt-6-luna`。没有新增或重命名变量，不改变 writer、认证、数据库或对象存储配置。
- 新增离线排序诊断工具；它读取已有的人类聚合投票直方图，不生成个人评审身份，不写数据库，也不宣布正式校准成功。

## 固定公开基准与隔离

使用 [AVA-Huggingface 数据镜像](https://huggingface.co/datasets/trojblue/AVA-Huggingface) 的既有 1–10 分投票直方图。逐个核对投票总数和重算的均分，不把模型自评当作标签。镜像说明其自带 train/test 不是经过验证的正式划分，所以本轮自行固定开发集和每轮独立验证集，并检查 image ID、图片字节 SHA-256 与 RGB 内容 SHA-256 不重叠。

开发集为固定 8 张图，每轮验证集另取 8 张。按聚合均分的四个固定区间各取两张：<4.5、4.5–5.5、5.5–6.5、>=6.5；用固定 seed 的 SHA-256 次序选择，不依据模型结果删改样本。每张验证图每个流程独立请求三次，绕过产品缓存。人类均分、投票数和样本 ID 均不进入模型输入。

已查看的验证集不复用为下一候选的独立验证集。最终模型比较使用此前未用于候选选择的镜像 test rows 200–299 子集；先固定模型、输入、提示词和采用门槛，再查看结果。

## 候选结果与采用依据

| 候选 | 独立验证平均逐次 Spearman，原流程 → 候选 | 大差距排序正确率 | 重复极差 P95 | 决定 |
|---|---|---|---|---|
| 先证据后分数 + 五维细则 | 0.902 → 0.872 | 100% → 100% | 0.8 → 0.6 | 不采用，排序变差 |
| 只改证据输出顺序 | 0.529 → 0.407 | 83.3% → 79.4% | 1.0 → 0.8 | 不采用，排序变差 |
| 改用 GPT-6 Luna，原 rubric 不变 | 0.064 → 0.324 | 68.6% → 77.5% | 1.0 → 0.8 | 采用为局部指标改善的候选 |

不同表格行使用不同验证图片，不能跨行比较绝对指标来推断候选高低。GPT-6.1 Sol 只完成开发样本试验，没有独立验证，不采用，也不把它宣称为质量退化。

最终门槛在评分前固定：平均逐次 Spearman 至少增加 0.10；人类均分差距 >=1.0 的图片对排序正确率不下降；同图三次极差 P95 不增加；所有固定样本和重复均完整且来源一致。最终报告为 `DIAGNOSTIC_IMPROVEMENT`，不是专业校准 `PASS`。

8 张验证图共有 17 个大差距图片对，每轮各比较一次，共 51 次对比。主要指标逐次计算后取平均，另报三次均分的相关性，避免把波动掩盖在均分中。相同图片重复给出相同分数视为稳定；只有不同图片全部同分导致排序相关性无法定义时才缺少有效分母。

绝对一致性仍偏弱：最终逐次平均相关性只有 0.324。小样本、按分段抽样、题材混合和 AVA 比赛语境均限制外推，不能据此认定线上所有照片更准确，更不能认定 6–8 分集中的问题已全面解决。

## 信息损失控制

另用一张公开静物原图及其严重缩小、模糊和 JPEG 损伤变体，两种模型各独立评分三次。变体和原图属于同一内容组，不混入独立验证图片。

| 流程 | 原图技术分 | 损伤图技术分 | 原图总分 | 损伤图总分 |
|---|---|---|---|---|
| GPT-5.6 Luna | 7 / 7 / 7 | 1 / 1 / 2 | 7.8 / 7.6 / 7.8 | 4.2 / 3.8 / 4.4 |
| GPT-6 Luna | 6 / 6 / 6 | 2 / 2 / 2 | 6.8 / 6.8 / 7.0 | 4.8 / 3.6 / 4.2 |

两个模型每次都识别了技术信息损失。新模型在这个人工构造的极端损伤图上，总分波动为 1.2，旧模型为 0.6，因此没有声称所有输入都更稳定。这是仍需扩展评测的限制。

## 用量、费用和延迟

按 [官方 API 费率](https://developers.openai.com/api/docs/pricing)，新模型短上下文输入为 $0.10/M、输出 $0.50/M；长上下文为 $0.20/M、$0.75/M，切点为 272K 输入。旧模型已有估算费率为 $0.20/M、$1.20/M。

最终验证集两组各有 24 次 scorer 请求，无额外高分复核。实际用量对应的 Standard 未缓存折扣估算：原流程 $0.03254，新模型 $0.01086。平均供应商请求耗时为 18.07 秒和 20.48 秒，新模型在该实验中略慢。这些是模型用量与官方单价的本地估算，不等于中转接口账单或用户收费；没有修改用户额度或产品价格。
