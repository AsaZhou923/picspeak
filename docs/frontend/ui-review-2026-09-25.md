# 全站 UI 文案、按钮与操作入口审查

日期：2026-09-25。范围：前端审查、设计调整、实现与本地验证。交付目标为 `develop` 分支；生产部署与线上验证不在本次交付范围内。

## 结论

截图中的问题已在代码中确认：结果页把“加入长廊”放在页面底部独立的折叠区，而“分享设置”里只有“移出 Gallery”。所以未加入的作品会显示“未展示”和不可用的移出按钮，用户无法就地执行下一步。另一个条件会隐藏从长廊进入的作品拥有者操作。

现在结果页在照片/评分附近直接显示长廊按钮、当前状态、收藏、分享和下载入口；历史页也能就地确认加入长廊。公开长廊和分享链接保留各自的访问控制，界面说明其区别。

这次确认了 UI 与前端行为问题，没有读取或修改截图中那张照片的生产记录。浏览器验证使用本地生产构建、测试身份和拦截的 API 响应；测试图片来自项目已有示例。

设计依据：[DESIGN.md](../../DESIGN.md) 的信息层级、按钮、交互状态、内容语气与可访问性规则。核心原则是操作入口可见、动作名称对应结果、状态依据服务端数据。

| UI-05 | “分享链接”状态/动作混乱 | 未开启只显示创建；已开启显示复制、关闭和查看；无状态时显示重试；保留可手动复制的链接输入框 | `ReviewVisibilityPanel.tsx` |
| UI-06 | 历史页“加入”可能仅跳转 | 直接显示发布确认，确认后提交所选作品；同步收藏和公开状态；保护异步返回时的选中项 | `frontend/src/app/account/reviews/page.tsx` |

| UI-08 | 含糊或混用的 UI 术语 | 改为“优先改进”“分享与照片管理”“下载与打印”；中文使用长廊，日文使用ギャラリー；补齐重拍/个人主页等局部硬编码英文 | 结果、历史、个人主页、长廊、重拍相关文案 |

| UI-11 | 错误页两个不同动作都叫“返回首页” | 分别命名返回上一页、返回首页；三语同步 | `frontend/src/app/error/page.tsx` |

| UI-13 | 控件语义和图标误导 | 负面提示词换为设置图标；模型选择组增加名称；任务进度/错误补可访问语义；图标和点击目标使用现有组件规则 | 生成表单、模型选择、任务等待页、确认窗 |

### 浏览器交互证据

本地浏览器使用真实页面和点击/键盘操作，所有业务 API 被拦截，不执行线上公开、上传、计费或模型调用。

- 详情页 15 项断言：长廊入口不在折叠区且桌面首屏可见；打开/取消确认不提交；确认只提交一次；同步收藏；分享跳转移动焦点；创建链接；移出长廊保留分享链接；同步工具条；关闭所有公开访问；拒绝审核不冒充公开；加载错误不冒充私有且禁止变更；重试恢复。
- 历史页 3 项断言：原地确认并直接提交一次；保持历史页路径；移出后恢复加入按钮。
- 上传 3 项断言：处理中可见禁用状态；第二次拖放不启动并发读取；读取失败可见且释放输入锁。另手工驱动 CLI 键盘验证 Enter 打开选择器、错误后 Space 再次打开选择器。
- 桌面 1440×1000、手机 390×844 的结果页截图已检查，重要按钮不折叠，手机可直接看到长廊入口。

## 保留与限制

页面原有暖色摄影风格、响应式结构、账号权限、审核公开确认和三语能力保留。只改有可确认问题的入口、状态、文案与控件，没有为统一视觉而重写所有正常页面。

尚未验证真实生产账号、真实审核服务、真实支付、真实上传和三方登录完成后的全流程；不把本地模拟测试当作这些服务已上线的证明。截图中具体照片的生产公开状态没有被本任务改变。
